Lesson 5 — Training, Datasets, and Reproduction Details

Data preparation, architecture, optimization, splits, and evaluation datasets

← Previous lessonContentsNext →

1. MOODS pretraining data

The paper describes MOODS as a field dataset with PPG from approximately 120 participants, collected over as many as 100 days. It reports 822,247 four-minute segments and roughly 55,000 hours. Participant counts and segment counts must be interpreted separately: repeated windows from one participant are correlated observations.

2. Preprocessing

  • Original sampling rate: 100 Hz.
  • Resampling: 50 Hz.
  • Window duration: four minutes, non-overlapping.
  • Samples per window: 12,000.
  • Normalization: person-specific z-normalization as described.
  • The paper reports no signal-specific filtering in the stated preprocessing pipeline.

Person-specific normalization may depend on data beyond a single inference window. Deployment must specify which statistics are available at prediction time and whether the protocol can be reproduced causally.

3. Subject-wise split

The paper reports 84 training, 18 validation, and 18 test participants. Subject-level splitting is preferable to randomly splitting windows because random segment splits can leak participant-specific characteristics across train and test sets.

4. Motif-distance network

  • Approximately 127K parameters.
  • Five dilated convolution blocks; kernel size 15.
  • Feature dimension 64.
  • Reported training: 20 epochs, learning rate 0.001, batch size 16, Adam.
  • Temporal stride 10 in the described motif computation.
  • Reported training time around 10 hours.

5. Foundation encoder

  • 1D ResNet-26, 128 initial filters, kernel size 11.
  • Initial stride 2 and 12 residual blocks as described.
  • 512-dimensional embedding; approximately 28.5M parameters.
  • Adam, reported learning rate 0.0001 and batch size 64.
  • The paper discusses a 20-epoch search configuration and reports final training with six epochs; reported training time is around five days on an NVIDIA L40S.

6. Downstream datasets

The paper evaluates on MOODS and external datasets including PPG-DaLiA, WESAD, SDB, and PPG-BP. Tasks include activity, stress, sleep-related prediction, heart-rate estimation, and blood-pressure-related regression. Dataset-specific labels and protocols matter: the same task name does not guarantee the same target construction.

7. Linear probing and fine-tuning

Linear probing (LP) freezes the pretrained encoder and trains a lightweight task-specific head. It tests how accessible task-relevant information is in the existing representation.

Fine-tuning (FT) updates some or all of the pretrained encoder using downstream data. It can improve performance, but depends more strongly on downstream data volume, regularization, and split protocol.

8. Reproduction checklist

  • Record data versions and subject IDs in each split.
  • Verify sampling rate and resampling implementation.
  • Verify window length, overlap, and dropped-window rules.
  • Match normalization exactly, including when statistics are computed.
  • Record model configuration, checkpoint, optimizer, schedule, and seeds.
  • Check subject, session, and device leakage.
  • Report participant count and segment count separately.
Important distinction

Open-source code and pretrained weights do not necessarily mean the original raw MOODS training data are publicly downloadable. Confirm access rights and data-use restrictions separately.
