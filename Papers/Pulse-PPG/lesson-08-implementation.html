Lesson 8 — From Paper to Code

Reproducing Pulse-PPG and building a controlled research extension

← Previous lessonContentsAdditional resources →

1. Three levels of implementation

  1. Use the pretrained model: load weights, extract embeddings, evaluate downstream tasks.
  2. Reproduce the paper: recreate preprocessing, motif-distance training, foundation pretraining, and evaluation.
  3. Extend the method: modify one scientific component and test whether it produces a measurable improvement.

A sensible progression is pretrained inference, faithful downstream baseline, then full pretraining if data and compute permit.

2. Official repository

Official Pulse-PPG GitHub repository.

  • run_exp.py — main experiment launcher.
  • pulseppg/models/RelCon/ — relative contrastive training.
  • pulseppg/models/MotifDist/ — motif-distance model.
  • pulseppg/nets/ — network backbones.
  • pulseppg/data/process/ — data processing.
  • pulseppg/eval/ — evaluation pipeline.
  • pulseppg/experiments/configs/ — experiment configurations.

The README documents pretrained weights hosted on Zenodo, a Conda environment, public evaluation-data processing scripts, and commands for evaluation and retraining. It describes custom-dataset evaluation as currently supporting linear probing, with fine-tuning support described as planned. Verify current repository state before executing commands.

3. Environment setup

git clone https://github.com/maxxu05/pulseppg.git
cd pulseppg
conda env create -f env.yml
conda activate pulseppg
pip install -e .

The README has referred to more than one download-script filename in different repository views. Inspect current files rather than assuming the name. Record version and environment:

git rev-parse HEAD
conda env export > environment.yml
python --version

Also record GPU model, CUDA version, seeds, and checkpoint identity.

4. Start with provided evaluation

python run_exp.py --config pulseppg --retrain_eval

Use this as an initial baseline only after checking current README/config semantics. The repository documents processing scripts for PPG-BP, PPG-DaLiA, SDB, and WESAD. For each run, record dataset/task, subject split, preprocessing, normalization, frozen/trainable encoder status, checkpoint, metric, and seed. Do not compare with the paper until splits, preprocessing, labels, and metric definitions match.

5. Integrate a custom dataset

The README describes adding a dataset under pulseppg/data/datasets and defining an Eval_Config in experiments/out/PulsePPG_expconfigs.py. It describes a pretraining hierarchy:

train/
  subject_id/
    data_input_0.npy
    data_input_1.npy
    ...

Use the example processing file as a reference. Verify loader assumptions: array shape, dtype, sampling rate, channel convention, missing values, and whether normalization is per-window or per-subject.

6. Full pretraining

The documented sequence is motif-distance training followed by Pulse-PPG training:

python run_exp.py --config motifdist --retrain
python run_exp.py --config pulseppg --retrain

The README describes support for different input lengths because of temporal pooling and gives 30 seconds as an example. Changing window duration nevertheless changes context, motif distributions, and possibly learned invariances. Treat it as an experimental variable. Open-source code and weights do not guarantee access to original MOODS raw data; check permissions separately.

7. Extension implementation plan

For temporal-order-aware motifs, locate the alignment/attention matrix in the motif-distance implementation. Add the regularizer behind a configuration flag so the original method remains unchanged when disabled.

Ltotal = LRelCon + λLorder

Test on small synthetic sequences with known monotonic alignment. Check gradients, numerical stability, memory, and λ = 0 equivalence before expensive pretraining.

8. Experiment matrix

ExperimentConfigurationPurpose
E0Original Pulse-PPGBaseline
E1Pulse-PPG + order penaltyMain method
E2Order penalty, λ = 0Implementation control
E3–E5Small, medium, large λSensitivity
E6Shuffled/random alignmentTest meaningful alignment

Evaluate representation quality, subject-independent transfer, cross-dataset transfer, and robustness to motion corruption, amplitude changes, missing segments, and window duration. Keep splits and training budgets matched; repeat key experiments across seeds.

9. Reproducibility protocol

  • Commit hash and environment file.
  • Dataset version, license, and split manifest.
  • Sampling rate, filtering, windowing, normalization, and label construction.
  • Model configuration, initialization, optimizer, scheduler, and checkpoint.
  • Random seeds and hardware.
  • Metrics, variation across seeds, and failure cases.
  • Compute cost: training time, memory, inference latency, and model size.

10. Research deliverables

  1. Working pretrained inference and embedding pipeline.
  2. Baseline result table traceable to code and splits.
  3. Clean extension branch/configuration flag.
  4. Ablation and robustness tables.
  5. Reproducibility report documenting deviations from the paper.
  6. Draft describing failure mode, method, experiments, and limitations.
Recommended next action

Start by running pretrained evaluation. Once the baseline is stable, inspect motif-distance code and implement the proposed order penalty behind a switch. This protects the original baseline and makes ablations credible.
